# Gather evidence around a question

Begin with the unknown that blocks the task. Search likely scopes for several related names
in one batch, inspect the most relevant callers and stop when the decision has enough evidence.
Do not reread an unchanged repository map or tool schema at every stage. Gather known
independent reads/searches together within scope and output limits; inspect every result,
including failures and truncation, before deciding. Defer dependent questions and stage
mutations, approvals and dependent checks separately.

Use deterministic lookup for literal names and file inventories. The portable locate command
can bound files, bytes and matches; inspect its coverage and truncation before interpreting a
negative result. Matching text is a lead, not proof of ownership or runtime reachability.

If extraction or classification needs a model, an authorized economical worker can receive a
narrow question, explicit paths and a source revision. Return a compact packet: cited locations,
short necessary excerpts, coverage limits and unresolved ambiguity. Keep architectural choices,
product interpretation and correctness decisions with the main reasoner. Do not send the full
conversation merely to perform a bounded search.

Reuse that packet until relevant files, scope or configuration change. Prepare configured
CLI/MCP metadata once at session start or first need and refresh affected bindings after tool,
account or authorization changes. Cache facts with identity and freshness; summaries neither
create policy nor renew authorization. Checkpoint only explicit useful metadata, not credentials
or complete transcripts.

## Assign work that can finish independently

Delegate when a bounded extraction, review or implementation can proceed independently and
the expected benefit exceeds coordination and context cost. Use deterministic batching first
for mechanical work. Keep a small tightly coupled task with one owner rather than inventing
parallel assignments. Host support, configured profiles and existing authorization still apply.

Give a worker the desired outcome, source/base identity, owned paths, applicable decisions,
acceptance checks, permitted effects and compact return format. Identify shared files and
dependencies before starting; serialize overlaps or designate one writer. A lookup worker
returns evidence, not an unrequested code change.

For parallel writers, follow [Git/worktree isolation](git-discipline.md#parallel-changes-and-worktrees).
Return the workspace and base revision, changed paths or commits, actual checks, assumptions
and unresolved issues; retain large logs as artifacts. Cite findings and coverage limits,
and resolve conflicting decision-critical citations against source. The coordinator reviews
the result and verifies the integrated state.
Delegation does not transfer responsibility for architecture, acceptance or publication.

## Preserve continuity and bound retries

Keep selected-guidance estimates, observed current-context occupancy and pack activity separate.
Unknown host telemetry remains unknown. Prefer a safe boundary for compaction; finish a useful
bounded step first. Save a small continuation checkpoint before replacing context: goal, state,
completed work, approach, evidence identifiers, changed paths, validation, remaining work,
blockers and next step. Preserve authorization limits in task metadata. Resume by comparing
the checkpoint with current Git/index/worktree state and pending acceptance, then load only
needed guidance. File freshness cannot establish the summary's semantic accuracy; review it.

Reliable native compaction favors saving continuation then compacting at a safe boundary.
Persistent rediscovery after compaction, stale assumptions or a major phase change favors a
saved handoff and fresh session. Near completion, finish the authorized task. Unknown occupancy
does not prevent a phase handoff, but cumulative tokens, session age, cache-hit percentage and
document estimates cannot prove saturation. Auto-compaction is a host capability, not a Pack
operation or guarantee. Use supported lifecycle checkpoint hooks where available and save
semantic progress proactively. If compaction precedes a fresh save, recover the last checkpoint,
verify it against current files and surface gaps. Recommend only supported controls; do not
change automatic-compaction settings. An unfinished task remains unfinished after session end.

Use declared operation attempt limits. After a no-progress attempt, inspect evidence and
change approach; at exhaustion return control or use evidence-bound configured model advice.
Changing models cannot resolve a missing permission or tool. Escalation requires current-target
quality evidence or missing declared capability, not discomfort or session age. Repeated lookup
alone is not provider token telemetry. Invalidate evidence when its files, revision, module
configuration, manifest or task identity changes.
