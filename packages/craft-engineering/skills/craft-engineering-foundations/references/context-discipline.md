# Gather evidence around a question

Begin with the unknown that blocks the task. Search likely scopes for several related names
in one batch, inspect the most relevant callers and stop when the decision has enough evidence.
Do not reread an unchanged repository map or tool schema at every stage.

Use deterministic lookup for literal names and file inventories. The portable locate command
can bound files, bytes and matches; inspect its coverage and truncation before interpreting a
negative result. Matching text is a lead, not proof of ownership or runtime reachability.

If extraction or classification needs a model, an authorized economical worker can receive a
narrow question, explicit paths and a source revision. Return a compact packet: cited locations,
short necessary excerpts, coverage limits and unresolved ambiguity. Keep architectural choices,
product interpretation and correctness decisions with the main reasoner. Do not send the full
conversation merely to perform a bounded search.

Reuse that packet until relevant files, scope or configuration change. Prepare configured
CLI/MCP metadata once at session start or first need and refresh affected bindings after tool,
account or authorization changes. Cache facts with identity and freshness; summaries neither
create policy nor renew authorization. Checkpoint only explicit useful metadata, not credentials
or complete transcripts.

## Assign work that can finish independently

Delegate when a bounded extraction, review or implementation can proceed independently and
the expected benefit exceeds coordination and context cost. Use deterministic batching first
for mechanical work. Keep a small tightly coupled task with one owner rather than inventing
parallel assignments. Host support, configured profiles and existing authorization still apply.

Give a worker the desired outcome, source/base identity, owned paths, applicable decisions,
acceptance checks, permitted effects and compact return format. Identify shared files and
dependencies before starting; serialize overlaps or designate one writer. A lookup worker
returns evidence, not an unrequested code change.

For parallel writers, follow [Git/worktree isolation](git-discipline.md#parallel-changes-and-worktrees).
Return the workspace and base revision, changed paths or commits, actual checks, assumptions
and unresolved issues. The coordinator reviews the result and verifies the integrated state.
Delegation does not transfer responsibility for architecture, acceptance or publication.
